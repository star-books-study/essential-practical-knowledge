# 8장. 실무에서 꼭 필요한 보안지식

## 중요한 보안

- **사례 1**
  - 요금 정보 API는 다음과 같았음
    ```
    https://주소/...?cd=고객 코드
    ```
  - 고객 코드가 로그인한 사용자의 고객 코드인지 검증하지 않고 고객 코드에 해당하는 고객 정보 응답
  - 무작위로 만든 코드가 고객 코드와 일치하면 해당 고객 정보 취득 가능

- **사례 2**
  - 암호 변경 API에서 회원 식별자와 변경할 암호 두 파라미터를 전달 받았음
  - 문제
    - 현재 요청이 로그인한 회원의 요청인지 확인하지 않음
    - 회원 식별자가 로그인한 회원의 식별자인지 검증하지 않음
    - 변경하기 전 암호를 검증하지 않음

- 보안 사고가 발생할 가능성을 낮추려면 서버 개발자는 기본적인 보안에 신경 써야 한다.

## 인증과 인가

### 인증과 토큰
- 로그인 과정
  - 서버는 클라이언트에 문자열로 된 토큰 제공
  - 클라이언트는 이후 각 요청마다 이 토큰을 함께 보내 자신이 누구인지 증명
  - 매번 아이디와 암호를 입력받지 않고, 토큰을 사용해 사용자 식별

- 토큰과 사용자 간의 매핑 정보는 어디에 저장해야 할까?
  - 서버의 별도 저장소
  - 토큰 자체에 저장
